안녕하세요.

공공데이터포털의 **한국관광공사_두루누비 정보 서비스_GW**(서비스ID: Durunubi)를
활용해 개발 중인 개발자입니다. 코스 목록 조회 결과와 관련해 두 가지 문의드립니다.

## 1. 제공 건수 불일치

서비스 설명에는 코리아둘레길 **284개 코스**의 GPX 정보를 제공한다고 안내되어 있으나,
`courseList` 오퍼레이션의 실제 응답은 `totalCount = 144` 로 고정됩니다.

확인한 내용은 다음과 같습니다.

- `numOfRows`/`pageNo` 를 조합해도 유니크 코스는 144건
- `routeIdx` 별 조회 결과 합계도 144건 (남파랑길 31 / 서해랑길 44 / DMZ 평화의 길 30 / 해파랑길 39)
- `crsLevel` 1·2·3 의 `totalCount` 합계도 정확히 144

또한 두루누비 홈페이지에는 존재하는 코스가 API에서는 조회되지 않습니다.
예를 들어 **해파랑길 3코스**(`T_CRS_MNG0000004228`)와 **해파랑길 5코스**(`T_CRS_MNG0000004190`)는
홈페이지에서 GPX와 함께 제공되고 있으나, `crsKorNm` 검색으로도 API에서는 조회되지 않습니다.

**활용 매뉴얼(v4.1)의 응답 명세에는 `totalCount` 샘플데이터가 740으로 기재**되어 있고,
매뉴얼의 요청/응답 예제 역시 자전거길 코스(**밀양강 자전거길**, `crsIdx=T_CRS_MNG0000005461`,
`brdDiv=DNBW`)로 작성되어 있는데, 현재 이 코스는 API에서 조회되지 않습니다.

문의드립니다.

1. 현재 API가 제공하는 코스가 144건이 맞는지, 아니면 데이터 동기화 문제인지
2. 서비스 설명의 284개 코스 전체를 조회할 수 있는 방법이 있는지
3. **운영계정으로 전환할 경우 조회 가능한 데이터 범위가 달라지는지**
   (매뉴얼상 계정 등급 차이는 트래픽에만 적용되는 것으로 이해하고 있습니다)

## 2. `brdDiv` 파라미터 동작 문의

매뉴얼상 `courseList` 의 `brdDiv` 는 걷기길(`DNWW`)/자전거길(`DNBW`)을 구분하는
옵션 파라미터로 기재되어 있으나, 실제로는 값에 관계없이 동일한 결과가 반환됩니다.

- `brdDiv=DNWW` → `totalCount=144`, 응답 항목의 `brdDiv` 는 모두 `DNWW`
- `brdDiv=DNBW` → `totalCount=144`, 응답 항목의 `brdDiv` 는 **여전히 모두 `DNWW`**
- `routeList` 에 `brdDiv=DNBW` 요청 시에는 0건 반환

자전거길 데이터가 현재 제공 중단된 것인지, 혹은 파라미터 처리에 문제가 있는 것인지
확인 부탁드립니다.
